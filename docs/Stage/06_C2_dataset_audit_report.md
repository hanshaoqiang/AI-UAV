## 1. 数据集完整性审查

### 1.1 数量关系核对（✅ 已确认自洽）

| 环节 | 数量 | 校验 |
|---|---|---|
| 原始采样 | 17242 | LHS seed=42，`n_sample = ceil(10000/0.58)` |
| 预筛拒绝 | 7078 | 推重比不足 3155 + 推力不足 1954 + 几何/重量 457 |
| 预筛通过（进入完整分析） | 10164 | 17242 − 7078 = 10164 ✓ |
| 有效样本 | 7387 | 入库成功 |
| 校验拒绝 | 2765 | 10164 − 7387 − 12 = 2765 ✓ |
| 失败 | 12 | 全部 `aero_failed`（VSPAero 极线未生成） |

10164 = 7387 + 2765 + 12 ✓；17242 = 7078 + 10164 ✓。预筛通过率 59.0%，完整分析有效率 72.7%，整体有效率 42.8%。

### 1.2 `--n-valid 10000` 的真实语义（⚠️ 已确认语义偏差）

`scripts/run_c2.py` 中：

```python
ap.add_argument("--n-valid", ..., help="目标有效样本数（预筛后进入完整分析）")
pass_rate_est = 0.58
n_sample = int(math.ceil(args.n_valid / pass_rate_est))
```

- `--n-valid` 只参与 `n_sample` 反推，反推分母是**预筛通过率 0.58**，因此 `--n-valid 10000` 的真实语义是「**预筛通过后进入完整分析的任务数 ≈ 10000**」，**不是**「最终有效样本数」。
- 实际结果：10164 组进入完整分析（≈10000），最终有效样本仅 **7387**。
- 数据集命名 `c2_10000_lhs` 与 docstring「10000 组有效数据」均与事实不符。若要以 10000 有效样本为目标，需 `n_sample ≈ 10000 / 0.4284 ≈ 23342`。
- **影响**：这是一处命名/文档/参数语义三重不一致，不影响数据本身，但会误导下游对数据规模的预期。

### 1.3 design_id 唯一性 / 元数据 / 断点恢复（✅ 基本正常）

- `design_id` 唯一：7387/7387（读回样本无重复）。
- 元数据完整：7387/7387（platform_version / sample_method / generated_at 齐全）。
- 断点恢复一致：state_file completed=10152，库中成功样本 7387 ≤ 10152（completed 含"成功 + 校验拒绝"两类，故大于库样本数属正常口径）。

### 1.4 失败记录完整性 = False（⚠️ 已确认是检查口径 bug）

`src/analysis/quality.py::database_quality()`：

```python
n_failed = int(stats["failed"]) + int(stats["rejected"])   # 12 + 2765 = 2777
failure_record_complete = len(self.failures) >= n_failed   # 12 >= 2777 → False
```

- 该检查把 **2765 个"校验拒绝"样本也当作"应记录的失败"**。但按 Decision 012，校验拒绝样本本就"不入库、不记录在 failures.json"（error 级样本写库前过滤）。
- `failures` 列表只有 12 条（12 个 `aero_failed`，且是 `finish_c2_report.py` 中**硬编码**的，见 1.5）。
- **结论**：12 个真实失败已完整记录，数据未丢失；是质量分析器的**口径 bug**——应改为 `len(failures) >= stats["failed"]`（仅对比真实失败数）。

### 1.5 数据库导出一致性（⚠️ 已确认缺失）

核查 `data/datasets/` 目录：

- `c2_10000_lhs.json` / `c2_10000_lhs.yaml` **不存在**（数据集未导出）。
- `c2_10000_lhs_failures.json` **不存在**（`_export_rejections` 未执行）。

## 2. BEMT 物理模型审查

### 2.1 定义与单位（✅ 正确）

- `thrust_power()` 返回 (推力 N, 轴功率 W, 效率)。`shaft_power = torque × ω`，`η = T·v / P_shaft`。
- 与 CT/CP 关系自洽：`η = (T·v)/(P) = (CT ρ n²D⁴ v)/(CP ρ n³D⁵) = J·CT/CP`（J 为前进比）。代码直接算 `T·v/P`，等价。
- 效率物理限幅 `[0, 0.95]`，风车状态（净推力 ≤ 0）返回 0。

### 2.2 径向离散与积分收敛（✅ 基本合理，1 处轻微问题）

- 径向离散：`n_sections=12`，从 `hub_ratio=0.15R` 到 `R` 均分，中点积分；忽略 0~0.15R 桨毂区（MODEL_LIMITATIONS 已声明）。
- **轻微问题（已确认）**：收敛判据写为
  ```python
  a = relax*a_new + (1-relax)*a
  if np.max(np.abs(a_new - a)) < tol: break
  ```
  因 `a` 已被松弛更新，实际判据等价于 `|a_new - a_old| < tol/(1-relax) = 0.0154`，比标称 `tol=1e-2` 松 ~54%。概念设计精度可接受，但非标称值。

### 2.3 Prandtl 桨尖损失（✅ 标准实现）

`F = 2/π·arccos(exp(-f))`，`f = (n_blades/2)·(R-r)/(r·sinφ)`，标准 Glauert 形式，下限钳制 `1e-6`。

### 2.4 诱导速度求解（⚠️ 线性化近似）

- 轴向/切向诱导因子用**线性化 Glauert 近似**：`a = σ·Cn/(4F·sin²φ − σ·Cn)`、`a' = σ·Ct/(4F·sinφ·cosφ + σ·Ct)`，未解完整二次方程。
- 高载荷区（a 大，如静止推力）精度下降，靠 `a_max=0.8` 钳制兜底。概念设计可接受，但**不可对标高精度 BEMT**。

### 2.5 XFOIL 极线查找表（✅ 覆盖 + ⚠️ 外推无物理）

- 表结构：5 Re（50k/100k/200k/300k/500k）× 36 α（−10°~25°），二维线性插值（log10(Re) + α）。
- Re 越界：钳制到边界；α 越界：**线性外推**（Cd 下限钳制 `1e-4`）。
- 问题（已确认）：桨根大攻角/高前进比（风车区）时 α 线性外推会产生无物理意义的 Cl/Cd，依赖"净推力 ≤ 0 返回 0"兜底，未对中间状态做物理修正。

### 2.6 0.75R 截面 5° 巡航桨距匹配（✅ 合理）

`_match_cruise_pitch()`：迭代 3 次，使巡航工作点（产生巡航推力所需转速）下 0.75R 截面攻角 = 5°，桨距比钳制 `[0.35, 2.0]` 防发散。方法合理。

### 2.7 高桨尖速度与可压缩性（⚠️ 已确认）

- docstring 明确「桨尖马赫 < 0.7 时可忽略压缩性修正」，即模型**不含压缩性修正**。
- **设计**桨尖速度可到 703 m/s（马赫 2.07），但见 2.8——实际工作转速被节流，工作桨尖马赫约 0.4，BEMT 在工作点有效。

### 2.8 多螺旋桨分配（✅ 一致，简化）

`evaluate()` 中所需推力按桨数**均分**，各桨独立求解；所有桨同直径/桨距/设计转速（`size_propulsion` 生成统一布局）。可用推力为各桨之和。简化但内部自洽，与"1~4 桨同规格"的 V1 范围一致。

### 2.9 桨尖速度 703.46 m/s 专项（⚠️ 已确认：真实映射但标签误导）

定位到样本 `c2_10000_lhs_002302`（run `20261126_002302_sampled_52af2f`）：

| 指标 | 值 |
|---|---|
| 直径 D | 1.500 m（钳制上限） |
| 设计转速 | 8957 rpm |
| **设计桨尖速度** | π×8957/60×1.5 = **703.5 m/s（马赫 2.07）** |
| 工作转速 operating_rpm | 1750 rpm |
| **实际工作桨尖速度** | 137.4 m/s（马赫 0.40） |
| 巡航功率 | 17.6 kW |

- **结论**：703.46 m/s 是**真实变量映射**（design_rpm × diameter），**不是单位、变量映射或数值计算错误**。
- 但它本质是「设计转速下的虚拟桨尖速度」——螺旋桨实际被节流到 1750 rpm（约为设计转速的 20%），从未到达该速度。
- **根因**：`quality.py::extract_physical_row` 用 `fp.get("rpm")`（= **设计转速**）计算 `tip_speed_ms`，而非 `prop_operating_rpm`。因此 `tip_speed_ms` 字段系统性高估实际桨尖速度约 5 倍。
- 分布：825 样本设计桨尖速度 > 250 m/s（马赫 0.73），227 个 > 400 m/s（超音速）。这些都是"设计转速下的虚拟值"。
- **影响**：`tip_speed_ms` 作为标签/特征会误导代理模型；建议改为工作桨尖速度，或明确重命名为 `tip_speed_design_ms` 并与 `tip_speed_operating_ms` 并存。

## 3. 气动与性能标签审查

### 3.1 AR→L/Dmax = 0.956（⚠️ 已确认"结构放大"）

- `LD_max` 直接取 VSPAero 极线的 `argmax(L/D)`（`vspaero/adapter.py::_fit`），而气动模型只含升力面（无机身，Decision 001），VLM 的 CD 几乎纯诱导阻力主导。
- 物理上 L/Dmax ∝ √(π·AR·e/Cd0)，高相关有真实物理根源；但被以下结构因素**放大**：
  1. **寄生阻力未进入 LD_max**（LD_max 是纯 VLM，不含组件叠加 CD0_parasitic）；翼型厚度、机身等寄生项对 L/Dmax 无贡献。
  2. 因此 taper→ld_max 仅 0.033、翼型/后掠/扭转对 L/Dmax 的影响被结构性稀释。
- 对照：`LD_cruise = CL/(CD_ind + CD0_parasitic)` 含寄生阻力，AR→LD_cruise 仅 0.649。
- **结论**：0.956 是「真实物理趋势 + 仅含诱导阻力的模型结构」共同作用，**不是 bug**，但 **LD_max 标签偏乐观（不含寄生阻力）且与 LD_cruise 口径不一致**，训练时二者不可混用。

### 3.2 诱导阻力 / 寄生阻力重复与遗漏（✅ 无重复计数）

- `_interp_polar` 只返回 `k_induced·CL²`（VLM 诱导阻力）；`CD0_parasitic` 由组件叠加法单独计入，`CD_total = CD_ind + CD_parasitic + CD_wave(≈0)`。无重复计数（Decision 013）。
- VLM 极线拟合截距 `CD0`（mean 0.0144）被识别为"数值伪零升阻力"，**未**与寄生阻力叠加 ✓。
- 隐含 Oswald 效率 `e = 1/(π·AR·k_induced)`：mean 0.799 / median 0.800，与 sizing 假设 0.85 接近，诱导阻力两侧建模一致。

### 3.3 静稳定裕度 1.362（⚠️ 有数据迹象，未确认）

- `static_margin_pre_trim = −Cmα_pre_trim/CLα`：min 0.149 / max **1.362** / mean 0.585。
- 物理含义：SM=1.36 表示中性点在重心后 1.36 倍弦长，远超常规固定翼（0.05~0.25）。447 个样本 SM_pre > 1.0。
- 数值来自 VLM 的 Cmα（关于配平前重心），未发现单位/公式错误；配平后 `static_margin` 恒 = 0.10（人为目标）。
- **判断**：属"配平前原始信号"，值本身计算正确，但分布偏高（配平前重心 25% MAC 与 VLM 中性点差距大），**需与手算/参考数据对比确认 VLM 中性点是否合理**，暂不判定为 bug。

### 3.4 static_margin_pre_trim / static_margin 区分（✅ 正确）

`_trim_cg` 配平前保留 `Cmα_pre_trim / NP_pre / CG_pre / cg_shift / static_margin_target`；数据库两列分开存（Decision 016）。配平后 `static_margin` 恒 = 0.10（常量列，已防御绘图）。区分正确。

### 3.5 续航 / 航程标签系统性偏低（🔴 已确认，重大）

实测（7387 有效样本）：

| 指标 | 值 |
|---|---|
| 航程达标率（predicted ≥ mission） | **44.7%**（3304/7387） |
| 续航达标率（predicted ≥ mission） | **0.3%**（23/7387） |
| 续航比 mean / median | 0.628 / 0.639 |
| 续航比分布 | <0.5×1586；0.5-0.75×4022；0.75-1.0×1756；≥1.0×23 |
| 螺旋桨效率 mean / median | 0.576 / 0.577（63% 样本 < 0.6） |
| 电机效率 mean | 0.837 |

- **系统性偏差**：预测续航均值仅为任务要求的 0.628 倍，几乎全部样本不达标。根因链：
  1. sizing 阶段电池按 `prop_eff=0.6` + `Oswald 0.85` + `motor_eff 0.85` 估算功率/能量；
  2. 实际 BEMT 巡航效率 mean 0.576（低于 0.6）、电机效率 0.837（低于 0.85）、且实际巡航阻力略高于 sizing 估算（隐含 Oswald 0.80 vs 0.85 + 收敛几何差异）；
  3. 三者叠加使实际功率高于估算，续航系统性缩水 ~37%。
- **为什么没被过滤**：`DataValidator` 把"航程达标/续航达标"设为 **warning 级（不过滤）**（Decision 012），预筛软约束亦仅告警。故大量"物理有效但严重不达标"样本进入"有效"集。
- **对训练的影响**：若代理模型目标是「满足任务需求的可行设计」，则达标样本极度稀疏（续航仅 0.3%），模型可能学不到"达标设计"的判别边界。这是**必须修复/明确决策**的问题。

## 5. 设计空间覆盖分析

### 5.1 采样覆盖（✅ 良好）

- 连续变量：LHS 均匀覆盖，min/max 与 `design_space.yaml` 一致（如 AR 6.5-14、taper 0.4-0.8、prop_rpm 4000-9000）。
- 离散变量：`airfoil_root` 24 类（663~767 次）、`airfoil_tip` 30 类（531~626 次）、`prop_layout` 4 类（4257~4403 次）、`n_props` 1~4，均均衡。

### 5.2 变量间相关（✅ 无隐含强约束）

- 采样阶段 LHS 正交，所有设计变量两两相关 |r| < 0.03（见 analysis.json 相关性矩阵），无隐含强约束。

### 5.3 预筛/校验导致的选择偏移（⚠️ 轻微偏移）

有效样本（7387）的 mission 变量分布 vs 原始采样：

| 变量 | 有效样本 mean | 原始采样 mean | 偏移 |
|---|---|---|---|
| cruise_speed_ms | 27.71 | 29.00 | 略偏低速（高速→功率大→易不可行） |
| payload_kg | 5.85 | 5.25 | 略偏高载（低载 <2kg 易几何不可行） |
| range_km / endurance_h / altitude_m | 175 / 1.78 / 1057 | 175 / 1.75 / 1050 | 基本无偏移 |

- 低载荷（<2kg）有效样本仅 655 个（8.9%），低于均匀采样的预期（约 15.8%）。
- 有效样本仍**覆盖完整设计空间**（AR 6.5-14、taper 0.4-0.8 全范围，见 1.3 物理表），未集中在狭窄区域。
- 预筛拒绝集中在"推重比不足（3155）/推力不足（1954）/几何重量（457）"，指向高速 + 高载荷边界。

**结论：设计空间覆盖良好，存在轻微的选择偏移（偏向低巡航速度、高载荷），对代理模型泛化影响有限但应知悉。**

## 7. 对代理模型训练的影响

1. **P1（续航偏低）影响最大**：达标样本极度稀疏（续航 0.3%），模型若以"任务达标"为监督目标将严重样本不平衡；且续航/航程标签带有系统偏差（非零均值噪声），需先厘清"sizing vs BEMT 效率不一致"再决定标签口径。
2. **P2（tip_speed 标签）**：`tip_speed_ms` 与 `prop_rpm × prop_diameter` 冗余且物理语义错误，应改用工作桨尖速度，否则模型学到伪关系。
3. **P6（LD_max）**：LD_max 不含寄生阻力、偏乐观，不可直接与 LD_cruise 混用作标签；应明确区分或补算"含寄生的 L/Dmax"。
4. **异常值（P1 字段重尾）**：mtow/power 需 log 变换或鲁棒缩放，避免高值尾巴主导梯度。
5. **P3/P4（记录缺失）**：不影响 7387 有效样本的训练，但削弱负样本/可追溯性。

---

## 8. 必须修复的问题（进入训练前）

1. **P1 续航/航程系统性偏低**：定位并修正 sizing 阶段功率/能量估算与 BEMT 实际效率的系统性不一致（或明确声明"有效样本≠任务达标样本"并据此设计训练目标/损失）。
2. **P2 `tip_speed_ms` 标签**：改用工作转速计算（或重命名为 `tip_speed_design_ms` 并存 `tip_speed_operating_ms`）。
3. **P4 数据集导出**：补生成 `c2_10000_lhs.json/.yaml` 与 `failures.json`，消除对脚本硬编码的依赖。

## 9. 可以暂时接受的问题

1. **P7 failure 口径 bug**：仅影响报告显示，不影响数据；可随下次质量分析一并修正。
2. **P8/P9/P11 BEMT 精度**：概念设计精度可接受；压缩性限制因实际工作桨尖马赫 ~0.4 而不触发（设计转速下的高桨尖速度不反映真实工作点）。
3. **P10 静稳定裕度偏高**：配平前原始信号，待外部验证，不阻塞（配平后已用目标 0.10）。
4. **P3 预筛拒绝记录缺失**：可接受（不影响有效样本），但建议下次采样时补录或在文档中声明缺口。
5. **P5 `--n-valid` 语义**：接受现状，但需在文档/命名中澄清，避免误读。

## 10. 下一阶段建议

1. **先修 P1 + P2 + P4，再进入 Phase 3**。
2. P1 修复前，建议做一次**抽样复算**（非全量）验证续航偏低根因——建议复核样本：`c2_10000_lhs_002302`（高桨尖速度）、`c2_10000_lhs_06421`（高功率）、`c2_10000_lhs_02413`（高 MTOW）各 1 组，对比 sizing 估算功率 vs BEMT 实际功率的差异构成。
3. P10 建议用 1~2 个已知构型（如典型 2m 翼展固定翼）手算中性点位置，对比 VLM 结果，确认 static_margin_pre_trim 分布是否合理。
4. 明确"有效样本"与"任务达标样本"的语义，决定训练标签口径（预测性能包络 vs 判别达标）。
5. 补全数据集导出与失败清单文件化，恢复完整可追溯性。
