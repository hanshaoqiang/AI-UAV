## 1. A1 巡航续航能力不一致诊断（核心）

### 1.1 三个代表性样本

| 样本 | design_id | 续航比 | 任务续航 | 预测续航 | 载荷/速度 |
|---|---|---|---|---|---|
| 明显不足 | `c2_10000_lhs_15220` | **0.097** | 2.30 h | 0.22 h | 6.2 kg / 35 m/s |
| 中位数 | `c2_10000_lhs_03480` | **0.639** | 1.15 h | 0.73 h | 5.1 kg / 26 m/s |
| 相对较好 | `c2_10000_lhs_15754` | **1.069** | 2.18 h | 2.33 h | 6.4 kg / 22 m/s |

### 1.2 完整计算链路（sizing 估算 vs 完整分析）

两条链路的续航一致等于同一物理量，可化简为（见 1.4 推导）：

```
续航比 = 预测续航/任务续航 = (drag_sizing / drag_actual)
         × (η_prop_actual / prop_efficiency) × (η_motor_actual / motor_efficiency)
```

三个样本的定量对比：

| 量 | 样本15220(不足) | 样本03480(中位) | 样本15754(较好) |
|---|---|---|---|
| drag_sizing / drag_actual | 0.972 | 0.944 | 0.998 |
| η_prop_actual | 0.710 | 0.612 | 0.683 |
| η_motor_actual | 0.683 | 0.848 | 0.819 |
| 公式推得续航比 | ~0.79 | ~0.78 | ~0.99 |
| **实际续航比** | **0.097** | **0.639** | **1.069** |

**关键矛盾**：公式推得的续航比（0.79 / 0.78 / 0.99）与实际（0.097 / 0.639 / 1.069）不符，说明还有一个**公式里没有的环节**在主导偏差——即**螺旋桨工作点的求解 overshoot**。

### 1.3 定量功率与能量平衡（定位偏差环节）

**样本 2（c2_10000_lhs_15220，D=1.5m 单桨，最严重）：**

| 环节 | sizing 估算 | 完整分析实际 | 比值 |
|---|---|---|---|
| 巡航阻力 | 23.97 N | 24.67 N | 0.97 |
| 所需推力 | 24.67 N | — | — |
| BEMT 实际推力 @1500rpm | — | **232.39 N** | **9.4× overshoot** |
| 轴功率 | 1394 W（=drag·v/0.6） | **11584 W** | 8.3× |
| 电机额定功率 | 4.182 kW | 11.58 kW（超载 2.75×） | — |
| 电功率 | 1726 W | 17841 W | 10.3× |
| 续航 | 2.30 h（目标） | 0.22 h | 0.097 |

**样本 1（c2_10000_lhs_03480，D=0.257m 双桨，中位）：**

|---|---|---|---|
| 巡航阻力 | 3.57 N | 3.78 N | 0.94 |
| 每桨所需推力 | 1.89 N | — | — |
| BEMT 实际推力 @6000rpm | — | 2.84 N | 1.50× overshoot |
| 电功率 | 193 W | 302.6 W | 1.57× |

**样本 3（c2_10000_lhs_15754，D=0.541m 单桨，达标）：**

|---|---|---|---|
| 巡航阻力 | 13.40 N | 13.43 N | 0.998 |
| BEMT 实际推力 @3000rpm | — | 13.76 N | 1.02×（几乎精确） |
| 电功率 | 601 W | 562 W | 0.94 |
| 续航 | 2.18 h（目标） | 2.33 h | 1.069 |

### 1.4 BEMT 推力-转速曲线陡变（根因实证）

BEMT 在低转速区（前进比 J = v/(n·D) 过高）进入风车状态，`thrust ≤ 0 → 返回 0`；脱离风车区后推力**急剧上升**：

```
样本2（D=1.5m, v=35m/s）：rpm≤1000 → T=0；1250rpm → T=18.4N；1500rpm → T=232N（1250→1500 突增 12.7 倍）
样本1（D=0.257m, v=26m/s）：rpm≤5000 → T=0；6000rpm → T=3.0N
```

而 `PropulsionModel._solve_propeller` 用 `_rpm_scan(design_rpm, lo=250, step=250)` 线性扫描，在推力陡变区以 250 rpm 步进，**跨过目标推力点后 overshoot 数倍**。

### 1.5 根本原因结论

1. **主导根因（D1，已确认）**：`_solve_propeller` 线性扫描（step=250）在 BEMT 风车→推力陡变区产生离散化 overshoot。大直径（D→1.5m 钳制上限）+ 单桨布局最严重（样本 2 达 9.4×）。
2. **次要根因（D2，已确认）**：`_solve_propeller` 只约束转速（≤ design_rpm），**不约束轴功率 ≤ 电机额定功率**，导致电机超载（样本 2 超载 2.75×）、`motor_efficiency` 因高 load_ratio 下降（0.683），进一步放大功率偏差。
3. **次要不一致（占比小）**：推进效率 η_prop（0.576 vs 0.6）、电机效率（0.837 vs 0.85）、阻力（drag_ratio 0.94~0.998）。这三项合计仅造成 ~20% 偏差，**不是**续航崩塌主因。

**性质判定**：这是**数值求解误差（overshoot）**，不是"任务物理不可行"。真实螺旋桨可精确调转速（如样本 2 约 1300 rpm）产生正好 24.67 N 推力，功率仅 ~1~2 kW。因此这些样本的"续航不足"是求解器 artifacts，修复后大部分会恢复。

> ⚠️ 重要更正：`06_C2_dataset_audit_report.md` 曾把续航偏低主因归为"推进效率差异 + 阻力低估"，经 Stage A 定量复核，**该判断不完整且偏误**，真正主导因素是工作点求解 overshoot。本报告以定量证据为准。

### 1.6 prop_efficiency 与 power_margin_factor 的真实作用

- `prop_efficiency=0.6`（`config.py` sizing）：**只用于 sizing 阶段**把气动阻力换算为轴功率 `p_cruise_w = drag·v/0.6`，进而决定电池能量 `e_req_wh` 与电机/电池质量。它**不参与**完整分析的功率/续航计算（完整分析用 BEMT 真实效率）。因此它是"定尺寸阶段对巡航桨效率的假设值"，物理上对应"桨巡航效率的预估中位"。
- `power_margin_factor=3.0`：`p_max_total = p_cruise_w × 3.0`，决定**电机额定功率**与电机质量，不代表续航计算。它保证电机额定功率 ≥ 巡航功率的 3 倍（配合 prop_efficiency=0.6，实际有效裕度 3.0/0.6=5.0）。
- 二者共同决定飞机重量（电池/电机质量）与电池容量，但不直接出现在续航公式中；续航偏差来自"实际功率 > sizing 估算功率"（因 overshoot）。

## 2. A2 BEMT 模型可信度检查

### 2.1 已确认的实现事实

| 项 | 实现 | 评价 |
|---|---|---|
| 极曲线来源 | Clark-Y，`build_prop_polar.py` 用 XFOIL 算 −6°~14° 稳定段；<−6° 线性外推；>14° 失速后用**硬编码经验斜率**外推（Cl −0.03/deg、Cd +0.02/deg） | 稳定段可信，失速后外推无物理依据 |
| 极曲线插值 | 5 Re（5e4~5e5）× 36 α（−10°~25°），log10(Re) 与 α 二维线性插值，越界外推/钳制 | 常规，α 外推无物理 |
| 弦长分布 | 线性 taper：`chord_ratio_75=0.12`、`chord_taper=0.5` | 经验形状 |
| 扭转分布 | 线性：0.75R 处由几何螺距定桨距角，`twist=−10°` 洗出 | 简化 |
| 径向离散 | `n_sections=12`，hub_ratio=0.15R 到 R 均分，中点积分 | 概念设计可接受 |
| 叶素动量方程 | 线性化 Glauert 近似：`a=σCn/(4F sin²φ−σCn)`、`a'=σCt/(4F sinφcosφ+σCt)`，`a_max=0.8` 钳制 | 高载荷精度下降 |
| Prandtl 桨尖损失 | `F=2/π·arccos(exp(−f))`，标准实现 | 正确 |
| 推力/扭矩/功率/效率 | `P_shaft=torque·ω`，`η=T·v/P_shaft`（=J·CT/CP），限幅 [0,0.95] | 自洽 |
| 可压缩性 | **未建模**（docstring 声明桨尖马赫<0.7 可忽略） | 设计转速下马赫可达 2，但工作转速下马赫≈0.4 |
| 多桨分配 | 所需推力均分，各桨独立求解，同规格 | 简化自洽 |
| 收敛 | max_iter=60, tol=1e-2, relax=0.35；收敛判据因松弛后判敛实际偏松 ~54% | 轻微 |

### 2.2 重点确认（针对任务问题）

1. **Clark-Y 极曲线是否只用于螺旋桨**：是。`prop_polar_table` 仅被 BEMT（PropulsionModel + FeasibilityPrefilter）消费；机翼/尾翼翼型走 UIUC 库 + XFOIL 独立分析（`airfoil_root/tip` 采样变量）。二者不混淆。
2. **0.75R 攻角=5° 是否被误认为全桨最优**：否。`_match_cruise_pitch` 仅用 0.75R 截面攻角 5° 作为**桨距匹配巡航点的策略**，文档明确这是匹配策略而非全桨优化。但桨叶其他截面攻角由线性扭转决定，非最优，属已知简化。
3. **高马赫未考虑压缩性**：是。设计转速下桨尖马赫可达 2.07，但实际工作转速被节流（工作桨尖马赫≈0.4），BEMT 在工作点有效；压缩性缺失不影响巡航结论，但若后续扩展到高桨尖速度工况需补修正。
4. **实验/公开基准验证**：**无**。`verify_bemt_calibration.py` 只验证"预筛通过率 + 误杀/误放率"，`tests/test_bemt.py` 只做单元/自洽校验。**没有任何实验数据或公开螺旋桨基准（如 APC 桨风洞数据）对标**。

### 2.3 验证缺口（明确列出，不编造）

- 未对标任何实验推力/扭矩/效率数据 → 无法判断 BEMT 绝对精度。
- 失速后极线（>14°）为经验外推 → 大攻角工况不可信。
- 线性化 Glauert 方程在静止/高载荷推力状态精度未知。
- **结论**：BEMT 通过了单元测试与内部自洽校验，但**未通过物理验证**；巡航工作点（桨尖马赫≈0.4、中低载荷）相对可信，但绝对精度需实验基准确认。

## 3. A3 桨尖速度指标检查

重点案例 `c2_10000_lhs_002302`（run `20261126_002302_sampled_52af2f`）：

| 量 | 值 | 来源字段 |
|---|---|---|
| 直径 | 1.500 m | `propellers[0].diameter_m` |
| 设计 RPM | 8957 | `propellers[0].rpm`（=prop_rpm 采样变量） |
| 实际工作 RPM | 1750 | `performances.prop_operating_rpm` |
| 原始桨尖速度（当前 tip_speed_ms） | **703.5 m/s（马赫 2.07）** | `quality.py` 用设计转速算：`π·(rpm/60)·D` |
| 实际工作桨尖速度 | **137.4 m/s（马赫 0.40）** | 应用工作转速算 |

- 字段使用情况：`tip_speed_ms` 仅由 `quality.py::extract_physical_row` 在质量分析时现算，不入库、不参与预筛硬约束（预筛中桨尖速度为软告警）、不参与 BEMT/性能计算。它只是**质量报告的一个展示指标**。
- 结论：`tip_speed_ms` 用**设计转速**计算，系统性高估实际工作桨尖速度约 5 倍，是**误导性标签**（非单位/数值错误）。

**建议字段方案（Stage B 实施）**：
- `tip_speed_design_ms`：`π·prop_design_rpm/60·D`（设计转速下的桨尖速度，反映设计约束上限）。
- `tip_speed_operating_ms`：`π·prop_operating_rpm/60·D`（实际工作转速下的桨尖速度，物理真实值）。
- 二者同时入库；质量分析/训练优先用 `tip_speed_operating_ms`。

## 4. A4 升阻比指标一致性检查

| 指标 | 公式 | 阻力组成 | 参考面积 | 数据来源 |
|---|---|---|---|---|
| `LD_max` | `argmax(L/D)` 取 VSPAero 极线 | **仅诱导阻力**（VLM 气动模型只含升力面，CD0 为数值伪零升阻力） | VSPAero 参考面积（升力面） | VSPAero .polar |
| `LD_cruise` | `CL/(CD_ind + CD0_parasitic)` | 诱导（VLM k·CL²）+ 寄生（组件叠加法） | 机翼平面面积 | VLM + ParasiteDragModel |

**明确回答**：

1. **可否直接比较？** 否。`LD_max` 不含寄生阻力（纯 VLM 升力面），`LD_cruise` 含寄生阻力；二者口径不一致，数值不可直接比较。
2. **LD_max 是否漏掉机身寄生阻力？** 是。VLM 气动模型仅升力面（机身闭合体被排除，Decision 001），机身/部件寄生阻力由 ParasiteDragModel 在 Performance 层计入 `LD_cruise`，但**未**计入 `LD_max`。故 `LD_max` 偏乐观，且 AR→LD_max 相关性 0.956 因此被"仅含诱导阻力"的结构放大。
3. **是否需重算含总阻力的 LD_max？** 建议是。方案二选一：
   - (a) 重算 `LD_max_total = max(CL/(CD_ind + CD0_parasitic))`（在极线各 α 点叠加寄生阻力后取最大）；
   - (b) 保留 VLM 的 `LD_max`，明确命名为 `LD_max_inviscid`，另存含寄生阻力的 `LD_max`。
4. **命名建议**：`LD_max`（含总阻力）、`LD_cruise`（巡航点）、`LD_max_inviscid`（纯 VLM，可选保留）。

## 5. A5 数据集完整性与统计问题

### 5.1 预筛选记录缺失（已确认）

- summary 声称拒绝 **7078** 条，DB `prefilter_rejections` 仅 **3612** 条，**缺 3466 条（49%）**。
- 按设计本应"全量入库"（Decision 018），缺失是生产事故（C2 崩溃 + `finish_c2_report.py` 未补录），非有意丢弃。
- 可否恢复：预筛是纯 Python 确定性计算（seed=42），**可从原始采样 + 预筛逻辑重放恢复**（无需重跑外部工具），但原始采样 LHS 需按 run_c2 同 seed 重新生成。这是 Stage B 的可选恢复路径。

### 5.2 预筛拒绝原因统计不一致（已确认根因）

报告"推重比不足×3155 + 推力不足×1954 + 几何/重量×457 = 5566"，与 7078 相差 1512。根因拆解：

- **5566 是 3612 条 DB 记录的失败原因标签总数**，不是 7078 条的统计。
- **多标签**：1954 条记录同时含"推力不足 + 推重比不足"（多标签率 1.541），故 5566 > 3612。
- **3466 条记录缺失**，其标签无从统计（若按多标签率外推，7078 条应有 ~10908 个标签）。
- **结论**：差异 = 「3466 条缺失记录」 + 「多标签导致标签数 > 记录数」两因素叠加，且报告把 3612 条记录的统计（5566）错配到 7078 条的语境。**不是拒绝原因本身统计错误，是记录缺失 + 口径混用**。

### 5.3 失败记录完整性（已确认）

- `failure_record_complete=False` 的判定：`quality.py` 计算 `n_failed = failed(12) + rejected(2765) = 2777`，然后 `12 >= 2777 → False`。
- 12 条失败样本（`c2_10000_lhs_01420` 等）**真实存在**：state 文件显示最后一次 resume 有 13 pending（12 failed + 1 rejected），12 个 design_id 均不在成功集（0/12 在 metadata）。失败阶段分类正确（全部 `aero_failed`，VSPAero 极线未生成）。
- **结论**：12 条失败记录完整、真实；False 是**质量分析器的判定口径 bug**（误把 2765 个"校验拒绝"样本计入"应记录的失败"，而这些样本本就不入库不记录）。应改为 `len(failures) >= stats["failed"]`。

### 5.4 异常值（已定位）

3 个异常字段（z-score>5）：`mtow_kg`(25, max 101.7kg=`c2_10000_lhs_02413`)、`tip_speed_ms`(25, max 703.5=`c2_10000_lhs_002302`)、`power_cruise_w`(75, max 26212W=`c2_10000_lhs_06421`)。均为重尾分布的正常高值尾巴，非数据错误；`tip_speed_ms` 的异常值根源即 D3（设计转速）。另 `static_margin_pre_trim`（max 1.362）未触发 z-score 但物理偏高，需外部验证。

### 5.5 `--n-valid` 语义（已确认）

`run_c2.py`：`n_sample = ceil(n_valid / 0.58)`，反推分母是**预筛通过率**，故 `--n-valid 10000` 实际控制"**预筛通过后进入完整分析的任务数≈10000**"，非"最终有效样本数"（实际 7387）。建议改名 `--n-tasks`（进入完整分析任务数）或 `--n-prefilter-passed`，并修正 help/docstring/数据集命名。

### 5.6 数据导出（已确认）

`DatasetGenerator._export` 支持 `yaml`/`json` 导出（**无 CSV**），`_export_rejections` 支持预筛拒绝/失败 JSON。C2 因崩溃未执行导出，导致 `c2_10000_lhs.json/.yaml/_failures.json` 均缺失。Stage B 需补：CSV + JSON 导出、失败清单文件化、字段定义字典。
